## 2. ما تقدمه كل بوابة الآن

### مالك المنصة `/platform`
- **الرئيسية:** المدارس والطلاب والمعلمون، وإيرادات الشهر وعمولاته ومصروفاته، والاشتراكات التي تنتهي خلال 30 يومًا.
- **المدارس:** إنشاء مدرسة مع مديرها، والإيقاف والتفعيل.
- **تفاصيل المدرسة:**
  - الاسم والميزات (Feature Flags).
  - المديرون: إضافتهم، وإعادة كلمة المرور، والإيقاف.
  - الاشتراك والتجديد.
- **الباقات:** سعر شهري وسنوي وميزات كل باقة. الاشتراك يطبّق ميزات الباقة على المدرسة تلقائيًا.
- **المالية:** كل الاشتراكات، ودفتر الحسابات (إيراد، مصروف، عمولة)، وإضافة قيود يدوية.

### إدارة المدرسة `/admin`
كل قسم يظهر حسب صلاحية المستخدم وباقة المدرسة.

- **الرئيسية:**
  - حضور اليوم.
  - ما يحتاج انتباهك: امتحانات بانتظار الاعتماد، فصول لم يُرصد حضورها، واجبات وامتحانات الأسبوع، التقارير المرسلة.
- **الهيكل الدراسي:** السنوات، والمراحل، والمواد، والفصول، وتوزيع المواد والمعلمين.
- **الجدول الدراسي:** الحصص، وأيام الدراسة، وجدول كل فصل مع منع تعارض المعلم.
- **الأشخاص:** الطلاب والمعلمون وأولياء الأمور والموظفون.
- **الأدوار والصلاحيات:** مصفوفة صلاحيات، وأدوار مخصصة، وصلاحيات فردية.
- **الحضور والغياب:** رصد يومي لأي يوم سابق، وتقرير شهري بنسب الالتزام.
- **الواجبات:** متابعة كل فصل ونسب التسليم.
- **الامتحانات:** طابور الاعتماد، والاعتماد أو الرفض مع ذكر السبب.
- **الدرجات:** كشف درجات لكل فصل ومادة.
- **التقارير الشهرية:** مراجعتها وإرسالها.
- **متابعة المعلمين:** الحضور المرصود، والحلول غير المصححة، والنتائج غير المنشورة، والتقارير غير المرسلة.
- **المالية:** بنود الرسوم، وحساب كل طالب (المستحق والمدفوع والمتبقي)، وتسجيل الدفعات وسجلها.
- **إعدادات المدرسة:** الاسم، والمنطقة الزمنية، والألوان، والشعار، مع إعادة التلوين فورًا.

### المعلم `/teacher`
- **الرئيسية:** حصص اليوم، وفصول لم يُرصد حضورها، وحلول تنتظر التصحيح، وامتحانات قريبة، ونتائج لم تُنشر.
- **فصولي** و**جدولي**.
- **الحضور:** رصد حضور اليوم. الجميع حاضر افتراضيًا ويعدّل المعلم الاستثناءات فقط.
- **الواجبات:** نشرها مع المرفقات، والتصحيح والتقييم.
- **الامتحانات:**
  - امتحانات ورقية وإلكترونية: شهري، ونصف الفصل، ونهائي، واختبار قصير.
  - بنك الأسئلة.
  - الإرسال للاعتماد، ورصد الدرجات، ونشر النتائج.
- **الدرجات:** كشف درجات مواده.
- **التقارير الشهرية:** تقييمات بالنجوم وملاحظات، وإرسالها لأولياء الأمور.

### الطالب `/student`
- **الرئيسية:** نسبة الحضور، والغياب، والواجبات المطلوبة، والامتحانات القادمة، وحصص اليوم.
- **موادي** و**جدولي**.
- **الحضور:** السجل والنسبة.
- **الواجبات:** تسليم نص ومرفقات حتى يُقيَّم الحل.
- **الامتحانات:** قاعة الامتحان الإلكتروني.
  - الإجابات تُحفظ على الجهاز.
  - تُرسل دفعة واحدة.
  - العد التنازلي يسلّم الامتحان تلقائيًا عند انتهاء الوقت.
- **درجاتي.**

### ولي الأمر (تطبيق الموبايل — لم يُبنَ بعد)
البيانات والصلاحيات جاهزة. ولي الأمر يقرأ بيانات أبنائه فقط:
- الحضور.
- الواجبات.
- الدرجات المنشورة.
- التقارير المرسلة.
- الرسوم والمدفوعات.

وتصله الإشعارات التالية:
- الغياب.
- عدم تسليم واجب.
- الدرجات.
- التقرير الشهري.

## 3. المعمارية باختصار

### Monorepo
مبني على npm workspaces و Turborepo:
- `apps/web`: Next.js 16 (App Router)، next-intl (العربية افتراضيًا و RTL)، Tailwind v4، shadcn، TanStack Query، react-hook-form + zod.
- `packages/core`: الأنواع، و zod schemas، وكتالوج الصلاحيات والميزات. مشتركة مع الموبايل لاحقًا.
- `packages/api`: طبقة الخدمات. **المكان الوحيد** الذي يتعامل مع Supabase.
- `supabase/`: الـ migrations واختبارات pgTAP.

### الأمان
- RLS على كل جدول.
- `school_id` في كل جدول، و FKs مركّبة.
- منع حذف البيانات المستخدمة بـ FKs من نوع DEFERRABLE.
- **الصلاحيات** تُفرض في ثلاث طبقات:
  - إخفاء عناصر القائمة.
  - حماية الصفحة على السيرفر.
  - RLS في قاعدة البيانات.
- **الباقات** (الميزات) تُفرض بنفس الطبقات الثلاث، وفي DB بـ `private.has_feature()`.
- **دوال RPC من نوع security definer:** معدودة وموثّقة في DNA (البند 13)، وكل واحدة تتحقق من المدرسة والصلاحية بنفسها.
- **الملفات:**
  - شعارات المدارس في bucket عام.
  - مرفقات الواجبات في bucket خاص تُنزَّل بروابط موقّعة قصيرة العمر.
- **منع التلاعب:**
  - الطالب لا يرى أسئلة الامتحان مباشرة، ولا يعدّل درجته.
  - المصحح لا يعدّل حل الطالب.
  - النتائج المنشورة لا تتغير إلا بصلاحية `grades.edit`.

### الإشعارات
- جدول `notifications` تكتبه الـ Triggers فقط.
- مهمة pg_cron كل 30 دقيقة تنبّه أولياء الأمور بالواجبات غير المسلَّمة.

## 4. التشغيل والأوامر

```bash
npm install
npm run dev
```
الموقع على http://localhost:3000. ملفات البيئة المطلوبة:
- `apps/web/.env.local`: مفاتيح Supabase. غير مرفوع على git.
- `apps/web/.env.test.local`: حسابات الاختبار. غير مرفوع على git.

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

```bash
npx supabase db push --linked --yes
```
يطبّق migrations جديدة على المشروع السحابي.

```bash
npx supabase gen types typescript --linked --schema public > packages/api/src/database.types.ts
```

### ملاحظات مهمة
- **اختبارات pgTAP:** `npm run db:test` يحتاج Docker. بدونه يمكن تشغيل محتوى أي ملف في `supabase/tests` داخل كتلة `do $$ ... raise exception $$` على المشروع، فيتم التراجع عن كل شيء تلقائيًا.
- **رقم الإصدار:** رقم إصدار أي migration جديد يجب أن يكون **أكبر** من آخر إصدار على السيرفر. الحالي: `20261028210000`.
- **إعادة تحميل متكررة في وضع التطوير:** إذا أعادت الصفحات تحميل نفسها باستمرار، أوقف السيرفر واحذف `apps/web/.next/dev`.

### حسابات الاختبار
هي لبيئة التطوير فقط، وكلها في مدرسة «مدرسة الاختبار التجريبية». العناوين وكلمة المرور الموحدة موجودة في `apps/web/.env.test.local`، وهو غير مرفوع على git.

| الحساب | الدور |
|---|---|
| owner | مالك المنصة |
| admin | مدير المدرسة |
| admin2 | مدير المدرسة |
| staff | موظف بدور «مشرف أكاديمي» |
| teacher | معلم |
| teacher2 | معلم |
| student | طالب |
| student2 | طالب |
| parent | ولي أمر |
| parent2 | ولي أمر |

> لا تستخدم هذه الحسابات ولا كلمة مرورها الموحدة في الإنتاج.

## 5. ما تم التحقق منه في كل مرحلة
- **قاعدة البيانات:** اختبارات pgTAP لكل قاعدة صلاحيات وقيد عمل، منها:
  - عزل المدارس عن بعضها.
  - منع تعارض المعلم في الجدول.
  - الحضور لليوم فقط للمعلم.
  - قفل الحل بعد تقييمه.
  - دورة اعتماد الامتحان.
  - عدم رؤية الطالب للأسئلة.
  - قفل التقرير المرسل.
  - صلاحيات المالية.
- **الواجهة:** تجربة كل مسار في المتصفح بحساب كل دور معني.
- **محاولات التجاوز:** عبر REST API مباشرة لكل دور، مثل:
  - كتابة بلا صلاحية.
  - رفع ملف في مجلد شخص آخر.
  - قراءة بيانات طالب آخر.
- **Supabase Advisors:** لا توجد مشاكل غير مقصودة. التحذيرات المتبقية موثّقة ومقصودة:
  - دوال definer محددة.
  - حماية كلمات المرور المسرّبة معطلة عمدًا في بيئة التطوير.

## 6. المتبقي — P10 وما بعدها

### قبل الإطلاق (P10)
1. **مراجعة شاملة:** أمان، وأداء، وإمكانية الوصول، والوضع الإنجليزي و LTR في كل الصفحات.
2. **إعدادات الإنتاج في Supabase Auth:**
   - تفعيل Leaked Password Protection.
   - إيقاف حسابات الاختبار أو حذفها.
3. **النشر على Vercel:** متغيرات البيئة، ورابط الموقع في Supabase Auth (Site URL و Redirect URLs).
4. **اختبارات E2E:** إضافة Playwright للمسارات الحرجة (اختيارية لكنها مستحسنة).
5. **مراجعة تجربة الجوال:** الجداول عريضة لكنها تمرَّر داخل بطاقتها.

### خارج النطاق الحالي (مخطط له)
- **تطبيق ولي الأمر (React Native):** يعيد استخدام `packages/core` و `packages/api` كما هما، ويحتاج Push Notifications (مثل Expo + جدول tokens).
- **بوابة دفع إلكتروني فعلية:** الميزة `online_payments` موجودة، وطريقة الدفع `online` ونوع القيد `commission` جاهزان. ينقص الربط مع مزوّد الدفع وتسجيل العمولة تلقائيًا.
- **المحاضرات الأونلاين:** الميزة `online_lectures` موجودة كعلامة فقط.
- **تحسينات مقترحة:**
  - تحديث لحظي للإشعارات عبر Supabase Realtime (حاليًا تحديث كل دقيقة).
  - دخول الطلاب باسم مستخدم بدل البريد.
  - خصومات أو منح على الرسوم.
  - عملة المدرسة في الإعدادات.
